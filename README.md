# image-processor — The Toy Gift Shop listing generator

Turn raw product photos into a complete, on-brand e-commerce listing set per
product — hero, white-background, detail, lifestyle, a titled hero, and a feature
infographic — plus a Shopify import CSV. Product photography is generated by
**fal.ai (Qwen-Image-Edit)**, which re-stages the real product from your photos
(it is told never to add packaging, accessories or props); all text/graphics are
rendered locally in the store's look (Plus Jakarta Sans, navy/red/gold, Tabler
line icons).

---

## 1. Install (once)

```bash
git clone https://github.com/Shuraim66/image-processor.git
cd image-processor
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

First run downloads the rembg cutout model (~1 GB) once.

## 2. Accounts / keys you need

| For | What | Set it |
|-----|------|--------|
| Product **images** (fal) | a fal.ai API key | `export FAL_KEY=...` |
| Product **copy** (title, features…) | Ollama + a Qwen3-VL model, running locally | `ollama pull qwen3-vl:8b` |
| Brand watermark/badge | a transparent `logo.png` in the repo root | already included |

```bash
export FAL_KEY="your-fal-key"
# if your Ollama model has a different tag:
export OLLAMA_VLM="qwen3-vl:8b"          # e.g. qwen3-vl:8b-instruct-q4_K_M
```
No fal key? You can still run the **free** path — see §7.
No Ollama? Add `--no-ollama` for generic fallback copy.

## 3. Put your products in `input/`

**One folder per product**, named by SKU, with that product's photos inside:

```
input/
├── TGS-SCOOTER-LED-PINK/
│   ├── front.jpg            # the product itself — the main reference
│   ├── angle2.jpg
│   └── angle3.jpg           # a packaging photo here improves the copy
└── TGS-TUMBLER-BLACK-STRAW/
    └── ...
```

- **SKUs follow the store convention: `TGS-` + name** (like the live catalog's
  `TGS-CONNECT4`). The folder name *is* the SKU; `intake.py --name` adds the
  prefix for you.
- 1 photo is enough; more angles = better. Include a **packaging** shot if you
  have one — the analyzer reads the box text.
- `front.*` is the main reference, then `angle2`, `angle3`, … (natural order).
  Make `front` the product itself, not its box — or set `"hero_photo"` (below).

## 4. Run the whole catalog (bulk)

```bash
source .venv/bin/activate
export FAL_KEY="your-fal-key"
export OLLAMA_VLM="qwen3-vl:8b"

# 1) photos -> product.json (copy) for every product
python3 analyzer.py --all

# 2) generate the listing images for every product (fal)
python3 gallery_pipeline.py --bg-provider fal --per-product

# 3) build one Shopify import CSV for the whole catalog
python3 shopify_export.py --per-product --price 29.99 \
        --image-base-url https://your-image-host.com/toys/
```

That's it. To process **one** product only, add `--sku TGS-TUMBLER-BLACK-STRAW` to steps 1–3.

### What you get per product
Everything lands in the product's own folder, `input/<SKU>/output/`:

```
input/TGS-TUMBLER-BLACK-STRAW/
├── product.json                 # the copy (title, features, SEO, tags…)
└── output/
    ├── CatalogHero.png / _wm.png # hero on a studio podium (+watermarked)
    ├── WhiteBG.png               # clean white main (marketplace-safe, no watermark)
    ├── Detail.png / _wm.png      # close-up (+watermarked)
    ├── Lifestyle.png / _wm.png   # product where it's really used (+watermarked)
    ├── Hero_titled.png           # store-style: title + eyebrow + badge
    └── FeatureCard.png           # catalog infographic (title, icon features, thumbnails)
```
(Pass `--no-per-product` to write to `gallery_out/<SKU>/` instead.)

Images are **reused** on re-runs (never re-billed) — delete a slot PNG to regenerate it.
Every fal run is appended to **`processed_products.csv`** (SKU, status, images
generated/reused, estimated cost, error) — the record of what's been processed.

**Lifestyle settings** are picked per product from its SKU/title
(`LIFESTYLE_SCENES` in `fal_listing.py`): RC cars on a park path, drones in the
air, bath toys in a tub, die-cast models on a display shelf, and so on.

**Per-product overrides** — hand-edit `input/<SKU>/product.json` (kept on `--reanalyze`):
```json
"hero_photo": "angle2.jpeg",
"lifestyle_scene": "on a kitchen counter next to a window"
```

## 5. Uploading to Shopify

Shopify's importer fetches images over **HTTP**, so it needs **public URLs**:
1. Host the `output/` images somewhere public (Shopify Files, S3/R2, any static host).
2. Point `--image-base-url` at that folder, e.g. `https://cdn.example.com/toys/`.
   The CSV then references `…/toys/<SKU>/CatalogHero.png`, etc.
3. In Shopify: **Products → Import**, upload `shopify_import.csv`.

Without `--image-base-url` the CSV has local paths (fine for review, not for import).

## 6. Options & environment reference

`gallery_pipeline.py`:
| Flag | Meaning |
|------|---------|
| `--bg-provider fal` | fal product-in-scene set (recommended). Needs `FAL_KEY`. |
| `--bg-provider procedural` | free, offline template backgrounds (see §7) |
| `--sku <SKU>` | one product only (default: all under `input/`) |
| `--no-per-product` | write to `gallery_out/<SKU>/` instead of `input/<SKU>/output/` (the default) |
| `--no-ollama` | skip the analyzer; deterministic fallback copy |
| `--reanalyze` | re-run the analyzer even if `product.json` exists |

Environment variables:
| Var | Default | Purpose |
|-----|---------|---------|
| `FAL_KEY` | — | fal.ai key (fal images) |
| `OLLAMA_VLM` | `qwen3-vl:8b` | local vision model tag for copy |
| `OLLAMA_NUM_CTX` | `8192` | context size (raise for many photos) |
| `REMBG_MODEL` | (bria default) | set `u2netp` for a tiny/low-RAM cutout model |

FeatureCard and the titled hero use the storefront's look for every product:
Plus Jakarta Sans, navy/red/gold (`feature_card.py`), and a Tabler line icon
chosen from each feature's wording (`ICON_RULES`).

## 7. Free / offline path (no fal, no cost)

Generate everything locally with template backgrounds (lower realism than fal):

```bash
python3 analyzer.py --all                                   # or --no-ollama
python3 gallery_pipeline.py --bg-provider procedural --per-product
python3 shopify_export.py --per-product --price 29.99
```
This produces a 7-slot gallery (`01_main … 07_detail`) using drawn studio
backgrounds. Also: `--bg-provider folder` (drop your own scene images in
`backgrounds/`) and `--bg-provider drawthings` (local Draw Things — see
`DRAWTHINGS_SETUP.md`). Size-card numbers come from `specs.json`.

## 8. Costs & notes

- **fal**: $0.03 per megapixel; each 1024×1024 scene ≈ $0.03 → **~$0.12 per
  product** (4 scenes). Copy (Ollama) and all graphics are free.
- If downloads fail with `CERTIFICATE_VERIFY_FAILED`, you're on a python.org
  build without a CA store — the pipeline already downloads via `httpx`/certifi.
- **Ollama**: one call per product; local and free.
- Re-runs reuse existing images, so you only pay once per slot.
- ⚠️ Keep API keys out of the repo — pass them via environment variables only.

## 9. Project layout

```
input/<SKU>/           raw photos (one folder per product)   → product.json
analyzer.py            photos -> product.json (Qwen3-VL/Ollama)
gallery_pipeline.py    orchestrator (--bg-provider fal|procedural|folder|drawthings)
fal_listing.py         fal product-in-scene set + lifestyle scenes + FeatureCard + titled hero
feature_card.py        FeatureCard V2 + titled hero templates (brand fonts, icons)
intake.py              group an unsorted shoot into TGS-<name> product folders
verify_sort.py         flag folders that mix two products (printed-title check)
detect_variants.py     propose color-variant groups
processed_products.csv record of every fal run
make_hero.py           text/render helpers, derive_theme, product_style, fonts
providers.py           bare-background providers (procedural/folder/drawthings)
quality.py             per-product quality checks
shopify_export.py      product.json + images -> shopify_import.csv
specs.json             per-SKU size-card data (procedural path)
assets/fonts/          bundled fonts + Tabler icon font (licenses alongside)
logo.png               brand badge / watermark
```
